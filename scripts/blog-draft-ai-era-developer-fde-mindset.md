# AI 시대의 개발자는 어디로 가야 할까 — FDE에서 찾은 방향

## AI가 바꾸고 있는 개발의 현장

예전에는 기능을 만들 때 검색하고, 코드를 짜고, 오류를 고치는 데 시간이 많이 들었어요. 지금은 AI에게 요구사항을 설명하면 초안을 만들고, 테스트를 제안하고, 여러 파일에 걸친 수정까지 진행해요. [제 AI 사용 기록을 분석했을 때](/blog/how-ai-changed-my-work)도 구현뿐 아니라 조사, 화면 설계, 문서, 배포까지 AI와 함께하고 있었어요. 일하는 범위가 넓어진 거죠.

이 변화가 모두에게 똑같이 나타나는 건 아니에요. 그래도 [2025년 Stack Overflow 개발자 설문](https://survey.stackoverflow.co/2025/ai/)에서 응답자의 84%는 개발 과정에서 AI 도구를 사용하거나 사용할 계획이라고 답했어요. 동시에 AI 출력의 정확성을 신뢰한다는 응답보다 불신한다는 응답이 더 많았어요. 구현 속도는 빨라져도, 결과를 믿을 수 있는지 판단하는 일은 남아 있어요.

## 그래서 개발자는 무엇을 더 잘해야 할까요?

저는 **문제를 정확히 정의하고, 기술을 실제 업무에 연결하는 능력**이 더 중요해질 거라고 생각해요. AI는 요구사항을 바탕으로 코드를 만들 수 있지만, 그 요구사항이 진짜 문제를 설명하는지는 현장의 사람에게 물어봐야 해요. 업무 흐름이 왜 그렇게 굴러가는지, 어떤 예외가 중요한지, 성공을 무엇으로 판단할지도 알아야 하고요.

ERP에서 “주문 처리를 자동화해 주세요”라는 요청을 받았다고 해볼게요. 입력이 느린 건지, 승인 단계에서 멈추는 건지, 출고 데이터가 늦게 들어오는 건지에 따라 만들어야 할 것이 달라져요. 이걸 모르고 AI로 화면부터 만들면 빠르게 엉뚱한 기능을 완성할 수도 있어요. 배포 뒤에는 실제로 처리 시간이 줄었는지, 담당자가 계속 쓰는지도 봐야 하고요.

## FDE는 그 방향을 직무로 만든 사례예요

이런 역할을 생각하다가 FDE(Forward Deployed Engineer, 전진 배치 엔지니어)라는 직무에 눈길이 갔어요. [팔란티어의 FDE 채용 공고](https://jobs.lever.co/palantir/5168e8fd-fec1-4fea-b7a1-81bdaea65850)는 고객의 현실 속으로 들어가 문제를 이해하고, 맞춤형 애플리케이션과 실제 운영에 쓰일 솔루션을 만들며, 현장 사용자부터 의사결정자까지 협업하는 일을 설명해요.

제가 이해한 FDE의 핵심은 “고객 가까이에서 결과까지 책임지는 엔지니어”예요. 현장에서 문제를 듣고, 기존 데이터와 시스템을 파악하고, 필요한 기능을 만들어 배포해요. 이후 사용자가 제대로 활용하는지 살피고, 반복해서 발견한 제약은 제품팀과 공유할 수도 있어요. 물론 회사마다 역할의 범위는 달라요. 모든 FDE가 고객사에 상주하거나 같은 기술 스택을 쓰는 것은 아니에요.

FDE는 AI가 등장하기 전부터 있던 직무예요. 그런데 AI로 구현이 빨라진 지금, 왜 현장에 가까운 개발자가 필요한지 더 잘 보여준다고 느꼈어요. 코드를 쓸 줄 알아야 확인한 문제를 제품으로 옮길 수 있고, 도메인과 사람을 이해해야 무엇을 만들지도 결정할 수 있으니까요.

## 직함보다 일하는 방식을 배우고 싶어요

모든 개발자가 FDE가 될 필요는 없어요. 제품의 기반을 깊게 다듬는 엔지니어도 꼭 필요해요. 제가 배우고 싶은 건 직함보다 **문제 발견 → 구현 → 배포 → 사용 확인**까지 시야를 넓히는 방식이에요.

그래서 다음 기능을 만들 때는 먼저 “누가, 어떤 상황에서, 왜 불편한가?”를 묻고 싶어요. 착수 전에 성공 기준을 정하고, AI로 구현한 결과는 직접 검증하고, 배포 뒤에는 사용자 반응과 운영 지표를 확인하는 거예요. 잘 쓰이지 않는다면 코드를 더 붙이기 전에 처음 정의한 문제부터 다시 살펴보려고 해요.

AI가 발전할수록 제가 지향하는 개발자는 코드를 빨리 만드는 사람에 머물지 않아요. 사람의 문제를 이해하고, 기술로 풀고, 실제로 나아졌는지 확인하는 사람에 가까워요. FDE는 제가 그 방향을 고민할 때 참고할 만한 직무예요.
