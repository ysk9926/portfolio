# 베몽테스

카페24 기반 커머스의 구독 서비스 개발. 2인 개발팀에서 구독 로직과 관련 관리자 화면을 주력으로 담당했습니다.

- 개발 기간: 2025.05–2025.11
- 현재 상태: 운영 중
- 역할: 풀스택 개발 · 구독 로직 및 관리자 화면 주력 · 2인 팀
- 정리일: 2026.09.08

### 배경과 문제
회원이 여러 구독 상품을 이용하면서 상품별 회차와 등급·선물 혜택을 따로 관리해야 했습니다.

### 맡은 역할
회원·상품별 구독 구조와 주문 연동 로직을 구현하고, 관리자가 구독 상태와 혜택 규칙을 설정하는 화면을 개발했습니다.

### 해결 과정
- 구독 상품, 회원별 구독, 회차별 혜택 규칙을 분리했습니다.
- 구독 상태를 활성·일시정지·취소의 **3가지**로 관리하고, 생성 전 중복 확인과 소프트 삭제·복구 기능을 추가했습니다.
- 주문 정보에 따라 구독 회차를 갱신하고 해당 회차의 등급 규칙을 적용하도록 연결했습니다.
- 관리자 화면에서 등급 규칙과 선물 수량을 설정하고, 구독을 생성·수정·삭제·복구하도록 구현했습니다.

### 결과
회원·상품별로 구독 회차와 혜택을 관리하고, 삭제한 구독을 기존 정보로 복구할 수 있도록 구현했습니다.

### 운영 현황
현재 운영 중인 서비스입니다. **2026.09.03 04:46–09.08 01:27(한국시간)** 조회 구간의 서버 로그에서 주문 웹훅 **127회**, 중복을 제외한 주문 ID **126개**를 확인했습니다.

이 수치는 쇼핑몰 전체의 주문 이벤트 수신 규모이며, 구독 결제 건수나 ERP 연동 성공 건수를 뜻하지 않습니다.

## 운영 수치 집계 기준

- AWS `vemontes`, 서울 리전, 운영 서버 컨테이너의 읽기 전용 로그 집계. 개인정보·주문 ID 원문은 문서에 저장하지 않음.
- 요청 범위: 2026.09.01 01:27:42–09.08 01:27:42 KST. 실제 로그 시작: 09.03 04:46:20, 마지막 로그: 09.08 01:15:04. 따라서 완전한 7일·월간 지표로 표현하지 않음.
- 주문 웹훅 수신 127회, 고유 주문 ID 126개. 수신 로그의 주문 ID를 집합으로 중복 제거.
- ERP 오류 127회: `No EcountInfo found`. 구독 상품 판별 오류 4회: `JpaSystemException`. 전체 오류 발생률·주문 결제 실패율로 환산하지 않음.
- 웹훅 처리 완료 로그는 내부 오류 이후에도 출력됨. 정상 ERP 전송이나 구독 결제 성공의 증거로 사용하지 않음.
- 해당 구간에 조회한 구독 주문 처리·등급 변경 성공 마커는 발견되지 않음. 구독 미운영으로 단정하지 않으며 활성 회원 수는 미확인.
- 집계 SSM 명령 ID: `e49461da-bed6-4a41-925c-1ee2e0e78c67`, 오류 원인 마커 집계: `afbd223c-d358-485e-905a-d353fbc98e82`.
