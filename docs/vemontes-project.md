# 베몽테스

카페24 쇼핑몰에 구독·등급·선물 관리, 추천인 보상, Ecount ERP 연동과 Flutter 앱을 연결한 베몽테스 커머스 플랫폼. 주문 연동의 부분 실패 처리와 운영 화면 개선까지 담당했습니다.

- 역할: 풀스택 개발 (메인), 2인 개발
- 기간: 2025.05 ~ 2025.11
- 정리일: 2026-09-08

## STAR 프로젝트 경험

### 사례 1. 구독 운영 규칙을 관리 가능한 데이터로 구조화

**상황 (Situation)**
베몽테스의 쇼핑몰에는 회원별 구독 상태와 회차별 등급·선물 정책을 함께 관리할 운영 기능이 필요했습니다.

**과제 (Task)**
저는 풀스택 메인 개발자로서 구독 상품, 회원별 상태, 등급 규칙과 선물 정보를 서버와 관리자 화면으로 연결하는 작업을 맡았습니다.

**행동 (Action)**
구독 상품과 회원별 구독 정보를 분리하고 상태를 Enum으로 관리했습니다. 구독 관리의 소프트 삭제를 추가하고, 등급 규칙 삭제 시 연결된 선물 삭제와 선물 수량 입력을 반영했습니다. 관리자 화면에는 회원 등급과 선물 수량을 표시했습니다.

**결과 (Result)**
운영자가 구독 상태와 혜택 조건을 화면에서 관리할 수 있는 구조를 구현했습니다. 선물 수량과 삭제 관계를 데이터에 반영해 관련 정보를 함께 관리하도록 했습니다.

근거: server 145445d, c8b2c7b, f98d421 / client 5cf7e80, 98c4a24

### 사례 2. ERP 주문 연동의 부분 실패 처리

**상황 (Situation)**
카페24 주문을 Ecount로 전송할 때 상품 매핑에 실패하거나 일부 품목 처리에서 예외가 발생할 수 있었습니다.

**과제 (Task)**
저는 한 품목의 오류가 나머지 정상 품목 처리까지 막지 않도록 하고, 실패 내용을 운영자가 추적할 수 있게 만드는 작업을 맡았습니다.

**행동 (Action)**
품목별 예외를 분리해 정상 품목은 전송 목록에 담고 실패 품목은 별도 목록에 기록했습니다. 처리 결과에 성공·실패 개수를 포함하고 주문 웹훅에서 부분 실패 결과를 다루도록 수정했습니다. 이후 ERP 처리 대상을 테스트 사용자에서 전체 사용자로 확장했습니다.

**결과 (Result)**
일부 상품 매핑 실패 시에도 정상 품목의 ERP 등록을 진행하고 실패 항목을 구분하는 경로를 구현했습니다. 실제 장애 감소율이나 재처리 시간은 측정 자료가 없어 성과 수치로 제시하지 않습니다.

근거: server 2b7d151 (2025-07-25), bc53473 (2025-08-28)

### 사례 3. 추천 내역과 인쇄물 관리 화면 개선

**상황 (Situation)**
추천인 상세 내역은 한 번에 조회하는 구조였고, 인쇄물 검색은 입력값이 바로 조회 조건에 반영됐습니다. 인쇄물 API는 상품명을 경로 식별자로 사용했습니다.

**과제 (Task)**
저는 목록을 나누어 불러오도록 바꾸고 검색 요청 시점을 조절하며, 상품명 변경과 특수문자를 다룰 수 있도록 API와 화면을 함께 수정했습니다.

**행동 (Action)**
추천인 요약과 상세 목록 API를 분리하고 상세 패널에 무한 스크롤을 연결했습니다. 인쇄물 검색에는 500ms 디바운스와 대기 표시를 추가했습니다. 인쇄물 조회·수정·삭제는 ID 기준으로 바꾸고, 상품명 검색은 POST 본문으로 받도록 분리했으며 중복 이름 검사도 추가했습니다.

**결과 (Result)**
추천 내역을 페이지 단위로 불러오고, 검색 입력이 멈춘 뒤 조회하도록 변경했습니다. 인쇄물 관리 작업은 ID로 대상을 지정하고 상품명 검색은 별도 요청으로 처리하게 됐습니다.

근거: server bc53473, d265c7e / client fd11964, 24327d0

### 사례 4. Flutter WebView의 쿠키와 화면 수명 관리

**상황 (Situation)**
쇼핑몰을 Flutter WebView로 제공하면서 iOS 쿠키 처리와 화면 종료 시 WebView 정리가 필요했습니다.

**과제 (Task)**
저는 앱 안의 쇼핑몰 화면에서 쿠키 설정과 로딩·뒤로가기·종료 처리를 보완하는 작업을 맡았습니다.

**행동 (Action)**
쿠키를 읽어 속성과 함께 다시 설정하는 로직, 공유 쿠키 설정, 로딩 표시를 추가했습니다. 화면 종료 시 로딩을 중단하고 컨트롤러 참조를 정리했으며, 웹뷰 방문 이력이 있으면 이전 페이지로 이동하도록 처리했습니다.

**결과 (Result)**
앱의 쿠키 처리와 화면 진입·종료 동작을 코드에 반영했습니다. 로그인 유지율이나 기기별 결제 성공률은 검증 자료가 없어 개선 수치를 주장하지 않습니다.

근거: app 4bced02 (2025-07-31), lib/main.dart
