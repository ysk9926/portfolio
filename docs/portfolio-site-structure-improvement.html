PORTFOLIO · INFORMATION ARCHITECTURE

포트폴리오 사이트 구조 개선 계획

콘텐츠를 줄이는 대신, 첫 방문자가 개발자의 정체성과 대표 근거를 먼저 이해하도록 노출 순서를 바꿉니다. 아래 내용은 현재 구조에 대한 진단과 앞으로 적용할 설계입니다.

대상 · 윤승규 포트폴리오 사이트기준일 · 2026-09-25상태 · 구현 전 계획

메뉴 중복과 메시지 분산은 사용자 진단을 기준으로 정리했습니다. 홈의 섹션 순서, 프로젝트 날짜순 기본 뷰, 관리자 저장 방식, canonical·sitemap 구현 여부는 저장소 코드를 확인했습니다.

01 · CURRENT STATE

기존 페이지의 문제점

01

메시지 분산

첫 화면에서 ERP·AI·WebGL 등 여러 주제를 함께 강조해 지원 직무와 대표 강점을 파악하는 데 시간이 걸립니다.

02

메뉴 역할 중복

AI·About·Skills·Projects·Blog·Career·Archiving의 역할이 일부 겹칩니다. 첫 방문자가 탐색 순서를 스스로 정해야 합니다.

03

정보 우선순위 부재

도구·스킬 수와 활동량이 대표 프로젝트·문제 해결 근거보다 앞서 보여 핵심 경험이 뒤로 밀립니다.

겹치는 영역현재 읽히는 문제정리 기준
About ↔ Career경력 설명이 두 곳에 분산됩니다.About은 일하는 방식, Career는 회사별 이력과 성과.
AI ↔ Skills도구와 기술 스택이 강점보다 먼저 나열됩니다.Skills는 제품 개발 스택, AI Workflow는 업무 절차와 검증.
Archiving ↔ ActivityGitHub 링크와 활동량이 중복 강조됩니다.Archive는 자료 입구, Activity는 하위 근거.
Blog ↔ Archiving기록 성격의 콘텐츠가 분리 노출됩니다.자체 Blog URL은 유지하고 Archive에서 연결.

현재 홈 렌더 순서는 Hero → AI Workflow → About → Skills → Archiving → Activity → Projects → Career입니다. Projects의 기본 세로 타임라인은 시작일 기준으로 다시 정렬되므로 데이터 목록의 순서만 바꿔서는 대표 3건을 먼저 보여줄 수 없습니다.

02 · DIRECTION

개선 방향

Enterprise 시스템을 설계하고, AI로 개발 프로세스를 개선하는 풀스택 개발자보조 근거 문구: “2025년 5월부터 기업용 업무 시스템과 AI 프로젝트를 기획부터 운영까지 이끌고 있습니다.” 기존의 “11개월·14개” 문구는 현재 운영 데이터와 맞지 않아 제외합니다.
원칙첫 노출상세로 이동
정체성 → 근거직무 한 문장과 검증된 성과프로젝트 상세·경력 기록
대표 → 전체직무 관련 대표 프로젝트 3건전체 카드·타임라인·상세 URL
요약 → 상세Core Stack, AI 작업 절차와 사례전체 기술 근거, 도구·스킬·커맨드
기록의 한 입구Archive에 Blog·GitHub·App Store 등 연결자체 블로그 원문, Git 활동 히트맵

대표 프로젝트의 첫 선택 권장 순서는 B2B 수출입 커머스 운영 플랫폼 → 금융·세무 연동 API 플랫폼 → RAG 기반 AI 프로젝트입니다. 실제 공개 프로젝트의 제목과 ID를 확인한 뒤 관리자가 전체 목록에서 고르며, 세 항목은 코드에 고정하지 않습니다.

03 · IMPLEMENTATION PLAN

개선 계획

  1. 1단계 · 메시지와 메뉴

    히어로를 정체성·검증된 근거·대표 프로젝트 보기 순으로 편집합니다. 상단 메뉴를 About · Projects · Career · Skills · AI Workflow · Archive로 정리하고 홈 섹션도 같은 읽기 순서로 배치합니다.

    확인: 모바일·데스크톱 메뉴 6개와 각 앵커, 상세 페이지에서 홈으로 돌아오는 이동.
  2. 2단계 · 대표 프로젝트

    관리자 페이지에 “대표 프로젝트” 편집기를 추가합니다. 전체 프로젝트에서 서로 다른 3건을 선택하고 1~3순위를 변경해 저장합니다. 선택한 ID와 순서는 독립 설정으로 관리해 프로젝트 자동 동기화 후에도 유지합니다.

    확인: 저장·새로고침·순서 변경·중복 방지, 삭제된 프로젝트 경고. 설정 전에는 전체 목록부터 표시.
  3. 3단계 · 요약 계층

    Projects는 대표 3건 뒤에 전체 목록과 기존 뷰를 둡니다. Skills는 Core Stack을 먼저, 추가 사용 경험과 근거는 아래에 둡니다. AI Workflow는 핵심 문장·5단계 작업 방식·대표 자동화 3건을 먼저 보이고 전체 도구·스킬 목록은 하단에 둡니다.

    확인: 기존 프로젝트 모달·상세 URL과 기술·AI 세부 정보에 계속 접근 가능.
  4. 4단계 · 연결 정리

    Archive 아래에 Blog·GitHub·실제 운영 채널과 Activity를 모읍니다. 프로젝트와 게시된 관련 글을 명시적으로 연결하고 양쪽 상세 화면에서 왕복할 수 있게 합니다. About과 Career의 중복 문장을 정리합니다.

    확인: 관련 링크의 공개 상태와 404 여부, 기존 #activity 앵커.
  5. 5단계 · 검색·운영 검증

    새 대표 메시지에 맞춰 홈 메타·OG 문구를 조정합니다. 이미 구현된 canonical과 sitemap의 실제 출력을 점검합니다. 기존 분석 이벤트를 유지해 변경 전후의 프로젝트 상세 진입·블로그 이동·이력서 다운로드를 비교합니다.

    확인: lint·test·build와 주요 경로 수동 점검. Velog 요약본 병행은 별도 운영 선택.

대표 설정은 featured-projects: {"ids":[1,2,3]} 형태의 별도 저장 영역으로 계획합니다. 현재 프로젝트 저장·동기화가 프로젝트 행을 삭제하고 재삽입하므로 프로젝트 행의 단순 플래그는 설정을 잃을 수 있습니다. 예시 ID는 실제 ID가 아닙니다.

04 · TARGET STRUCTURE

개선 후 구조

상단 메뉴 · 6개 About · Projects · Career · Skills · AI Workflow · Archive

  1. Hero정체성·근거
  2. About일하는 방식
  3. Projects대표 3건 → 전체
  4. Career역할·성과
  5. SkillsCore → 경험
  6. AI Workflow요약 → 상세
  7. Archive기록·Activity
영역첫 화면의 핵심더 깊이 볼 경로
Projects관리자가 고른 대표 3건과 선택 순서전체 카드·시간순 타임라인·모달·개별 프로젝트 URL
Skills실제 주력 Core StackAlso Worked With와 프로젝트 사용 근거
AI Workflow5단계 작업 방식과 자동화 사례 3건도구·스킬 그룹·커맨드 전체 기록
ArchiveBlog·GitHub·App Store 등 운영 채널자체 블로그의 원문, Git 활동 히트맵

유지할 주소와 콘텐츠

  • /blog와 글 상세, /projects/[slug]는 유지합니다.
  • 프로젝트 상세 모달, 기술 사용 근거, AI 워크플로 기록, 기존 전체 프로젝트 뷰를 보존합니다.
  • 자체 블로그를 원문으로 유지합니다. Velog는 운영을 선택한 경우에만 요약·유입 채널로 사용합니다.
